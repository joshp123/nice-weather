2. Data pipeline outline

Use Go for orchestration, scoring, validation, artifact generation, with ecCodes/GDAL called as external tools for GRIB2 and raster handling. Do not write a GRIB decoder in Go for a POC.

Pipeline:

1. Fetch latest complete ICON-EU run
   - prefer 00/06/12/18 UTC runs because they provide +120h
   - required folders: t_2m, relhum_2m, tot_prec, clct, u_10m, v_10m

2. Decode GRIB2 to temporary rasters
   - validate CRS/grid
   - validate all required variables exist for every selected lead time

3. Build forecast WeatherInput grids
   - horizon now = rolling next-24h forecast window
   - d1..d5 = daily 24h windows
   - temp/humidity/cloud/wind = mean over window
   - rain = summed precipitation over window, normalized as mm/day

4. Load WorldClim monthly rasters
   - tavg, prec, srad, wind, vapr
   - 12 monthly files per variable

5. Build climatology WeatherInput grids
   - jan..dec = representative daily-normal input for that month
   - rain = monthly precipitation / days in month

6. Score each grid
   - profile general
   - profile cycling
   - same component scores, different weights

7. Render artifacts
   - score raster tiles
   - manifest.json
   - optional inspect grids for click details

DWD’s open-data ICON-EU parameter folders include the required forecast variables: clct, relhum_2m, t_2m, tot_prec, u_10m, and v_10m.

5. Exact source-field-to-WeatherInput mapping

Shared semantic contract:

TypeScript
type WeatherInput = {
  tempC: number;     // mean air temperature, °C
  humidity: number;  // relative humidity, %
  rainMm: number;    // precipitation, mm/day equivalent
  cloudPct: number;  // total cloud cover, %
  windKmh: number;   // wind speed, km/h
};
Forecast: DWD ICON-EU
WeatherInput field	ICON-EU source	Mapping
tempC	T_2M / t_2m	T_2M_K - 273.15
humidity	RELHUM_2M / relhum_2m	clamp(value, 0, 100)
rainMm	TOT_PREC / tot_prec	sum accumulated precipitation intervals; kg/m² == mm; normalize selected window to mm/day
cloudPct	CLCT / clct	clamp(value, 0, 100)
windKmh	U_10M, V_10M	sqrt(u² + v²) * 3.6
Climatology: WorldClim 2.1

WorldClim provides monthly tavg, prec, srad, wind, and vapr at multiple resolutions including 30 arc-seconds. 
WorldClim

WeatherInput field	WorldClim source	Mapping
tempC	tavg	tavg
humidity	vapr, tavg	100 * vapr_kPa / saturationVaporPressure(tavgC); clamp 0..100
rainMm	prec	prec_mm_month / daysInMonth
cloudPct	srad, latitude, month	derive cloudiness proxy from solar radiation ratio; see below
windKmh	wind	wind_mps * 3.6

Humidity formula:

saturationVaporPressure(T) = 0.6108 * exp((17.27 * T) / (T + 237.3))
humidity = 100 * vapr / saturationVaporPressure(tempC)

FAO defines relative humidity as actual vapor pressure divided by saturation vapor pressure at the same temperature, and gives the same saturation vapor pressure relationship. 
FAOHome
+1

Cloud proxy:

sradMJ = srad_kJ_m2_day / 1000
clearSkyMJ = 0.75 * extraterrestrialRadiationMJ(lat, month_midpoint)
ratio = clamp(sradMJ / clearSkyMJ, 0.33, 1.0)
cloudPct = 100 * (1 - ratio) / (1 - 0.33)

FAO notes that cloudless shortwave radiation is roughly 75% of extraterrestrial radiation, and that the ratio of measured solar radiation to clear-sky radiation expresses cloudiness, with smaller ratios meaning cloudier skies. 
FAOHome

6. Missing fields / approximation risks
Issue	Impact	POC handling
WorldClim has no direct cloud-cover field	Monthly cloudPct is approximate	Use srad-based proxy; mark climatology cloud as derived
WorldClim has vapor pressure, not RH	RH estimate is nonlinear and monthly-mean based	Use vapr / saturationVaporPressure(tavg); clamp and document
Forecast wind is 10 m; WorldClim wind may not match height semantics	Cycling comfort can be biased	Do not “correct” with fake precision; expose as source caveat
Forecast and climatology temporal semantics differ	Forecast is weather; climatology is normal	Keep basis explicit in UI; never blend the two
ICON-EU is ~6.5–7 km; WorldClim can be ~1 km	Mixed visual precision risk	POC product grid should be 0.0625° for both; metadata must show source resolution
Coastal/mountain microclimates	Score may be locally wrong	No false precision; show source and generated time
WorldClim commercial use	Product/legal risk	WorldClim says academic/non-commercial use is free; redistribution or commercial use requires permission. 
WorldClim
7. Minimal artifact format for frontend

Use one manifest plus raster tiles.

public/artifacts/
  manifest.json
  tiles/
    forecast/general/now/{z}/{x}/{y}.png
    forecast/general/d1/{z}/{x}/{y}.png
    forecast/cycling/d1/{z}/{x}/{y}.png
    climatology/general/jan/{z}/{x}/{y}.png
    climatology/cycling/jan/{z}/{x}/{y}.png

Example manifest.json:

JSON
{
  "version": 1,
  "generatedAt": "2026-04-27T10:00:00Z",
  "grid": {
    "crs": "EPSG:4326",
    "cellDeg": 0.0625,
    "region": "Europe"
  },
  "sources": {
    "forecast": {
      "name": "DWD ICON-EU",
      "run": "2026-04-27T06:00:00Z",
      "resolutionKmApprox": 6.5,
      "horizons": ["now", "d1", "d2", "d3", "d4", "d5"]
    },
    "climatology": {
      "name": "WorldClim 2.1",
      "period": "1970-2000",
      "sourceResolution": "30 arc-seconds",
      "renderedResolutionDeg": 0.0625,
      "horizons": ["jan", "feb", "mar", "apr", "may", "jun", "jul", "aug", "sep", "oct", "nov", "dec"]
    }
  },
  "layers": [
    {
      "basis": "forecast",
      "profile": "general",
      "horizon": "now",
      "tileUrl": "/artifacts/tiles/forecast/general/now/{z}/{x}/{y}.png"
    }
  ],
  "legend": {
    "min": 0,
    "max": 100,
    "labels": {
      "0": "bad",
      "50": "okay",
      "80": "good",
      "95": "excellent"
    }
  }
}

Tile pixel semantics:

RGBA PNG
alpha=0      -> no data / outside Europe
RGB color    -> score color
score source -> 0..100 uint8 before palette application

For POC, the frontend only needs manifest.json and PNG tiles.
